# AGIRE TAIRET — منصة إدارة الموارد المائية والعملاء

منصة ويب عربية/فرنسية لإدارة العملاء والفواتير والدفعات والديون وقراءات استهلاك المياه. بُنيت لتستخدمها عدة موظفين من أجهزة مختلفة عبر خادم مركزي؛ الموظف يفتحها في المتصفح ولا يحتاج إلى تثبيت برنامج عميل.

## ما يعمل في النسخة الحالية

- تسجيل دخول بحسابات فردية، أدوار (مدير، فوترة، قراءة فقط)، وقفل مؤقت بعد تكرار محاولات الدخول.
- إدارة بيانات العملاء وحالة الحساب، مع سجل تدقيق للتغييرات.
- فواتير ومدفوعات جزئية، وحساب الرصيد المتبقي.
- أرشيف شهري للفواتير حسب تاريخ الإصدار مع ملخص عدد الفواتير والإجمالي والتحصيل والمتبقي. تصدير Excel يتضمن ورقة أرشيف شهري.
- العملة الافتراضية للفواتير الجديدة هي الدينار الجزائري (DZD / دج)؛ يحتفظ كل سجل قديم بعملة الفاتورة الأصلية ولا تُحوّل المبالغ تلقائياً.
- تسجيل قراءة استهلاك شهرية وإنشاء فاتورة الاستهلاك تلقائياً.
- لوحة مؤشرات ورسوم، وتقارير Excel متعددة الصفحات بالعربية أو الفرنسية.
- مظهر فاتح/داكن بألوان مائية وحركة سائلة خفيفة؛ يحفظ المتصفح تفضيل المظهر محلياً ويحترم إعداد تقليل الحركة.
- PostgreSQL لتشغيل الخادم المشترك، وSQLite للتطوير المحلي فقط.

## التقنية والبنية

- ASP.NET Core Blazor Server على .NET 10.
- ASP.NET Core Identity للحسابات والجلسات، مع تخزين كلمات المرور بطريقة Identity.
- Entity Framework Core وPostgreSQL. لا تتصل أجهزة الموظفين بقاعدة البيانات مباشرة.
- واجهات عربية RTL وفرنسية LTR وملفات الواجهة الأمامية مضمنة محلياً.
- بنية المستودع:

```text
docs/                 دراسة المتطلبات والقرارات المعمارية بالعربية والفرنسية
prototype/            النموذج المرئي المرجعي السابق
src/web/Hawdh.Portal  تطبيق المنصة وقاعدة البيانات والواجهات
tests/                اختبارات تكامل للحسابات والبريد والصلاحيات وتصدير Excel
Hawdh.Platform.slnx   حل .NET
```

## تشغيل التطوير على جهاز واحد

يحتاج المطوّر إلى .NET 10 SDK فقط. في PowerShell من جذر المشروع:

```powershell
$env:SeedAdmin__Email = 'admin@example.local'
$env:SeedAdmin__Password = 'ضع-كلمة-مرور-تجريبية-قوية-هنا'
dotnet run --project src/web/Hawdh.Portal
```

افتح العنوان الذي يظهر في الطرفية. قاعدة SQLite تحفظ محلياً داخل `src/web/Hawdh.Portal/App_Data/`. لا تستخدم هذا الوضع للتشغيل المشترك أو لبيانات حقيقية.

إرسال روابط التأكيد والاستعادة في التطوير اختياري؛ عند الحاجة اضبط متغيرات `Smtp__Host` و`Smtp__Port` و`Smtp__Security` و`Smtp__FromAddress`، وأضف `Smtp__UserName` و`Smtp__Password` إذا كان الخادم يتطلب مصادقة. يدعم الإنتاج `StartTls` أو `SslOnConnect` فقط.

## تشغيل PostgreSQL محلياً عبر Docker Compose

هذا الإعداد للتطوير والمعاينة على الجهاز نفسه فقط. انسخ `.env.example` إلى `.env` وغيّر الأسرار التجريبية إلى قيم فريدة، ثم شغّل:

```powershell
Copy-Item .env.example .env
# عدّل .env وضع أسراراً قوية وفريدة
docker compose up -d --build
```

افتح `http://localhost:5080`. قاعدة البيانات لا تُعرض كمنفذ خارجي، والمنصة مربوطة على `localhost` عمداً. هذا الملف لا يهيئ شهادة TLS أو نسخاً احتياطية أو مراقبة إنتاجية.

## التكامل المستمر

يفعّل GitHub Actions عند كل push أو pull request: يستعيد الحزم مع تدقيق NuGet، ويتحقق من صياغة سكربتات النسخ والاستعادة وإعداد Compose الإنتاجي، ويرفض تنبيهات الثغرات المعروفة، ثم يبني نسخة Release ويشغّل اختبارات تكامل للتحقق من فرض MFA على المدير، وصلاحيات مستخدم الفوترة، وتغيير البريد عبر رمز تأكيد، وإرسال رابط بريد عبر SMTP، وصيغ ملفات Excel والترجمات المستخدمة، ويبني صورة Docker الإنتاجية. قواعد الاختبار SQLite وSMTP مؤقتة ومعزولة. يتابع Dependabot تحديثات NuGet وGitHub Actions أسبوعياً.

## نشر خاص متعدد الأجهزة عبر HTTPS

أضف سجلاً DNS من نوع A للنطاق الذي تملكه يشير إلى خادم النشر، وافتح المنفذين 80 و443 على الجدار الناري. على الخادم، انسخ `deploy/.env.production.example` إلى `deploy/.env.production`، واختر نطاقاً حقيقياً وكلمات مرور طويلة وفريدة، ثم نفّذ:

```bash
docker compose --env-file deploy/.env.production -f docker-compose.production.yml up -d --build
```

يوفر Caddy شهادة TLS تلقائياً. قاعدة PostgreSQL غير منشورة على منفذ خارجي، وخدمة الويب لا تُعرض إلا عبر Caddy. لا تفتح المنفذ 8080. يلزم أن يكون النطاق قابلاً للوصول من الإنترنت للتحقق الآلي من الشهادة؛ لاستضافة LAN فقط استخدم نطاقاً وشهادة صادرين عن جهة موثوقة لدى أجهزة الموظفين، أو هيّئ الوكيل بعناية وفق وثائق المؤسسة. إذا كان نطاق شبكة Docker `172.31.245.0/24` مستخدماً مسبقاً، غيّره بالتطابق في Compose و`ReverseProxy__KnownProxy`.

بعد أول تشغيل ناجح، تحقّق من إمكانية الدخول بحساب المدير، ثم أزل `SEED_ADMIN_PASSWORD` من ملف الإنتاج وأعد إنشاء حاوية الويب. خزّن ملف الأسرار خارج Git. مفاتيح ASP.NET Data Protection محفوظة في volume دائم، ويجب تقييد وصول النظام إليه وحمايته ضمن النسخ الاحتياطي.

أنشئ نسخة احتياطية من PostgreSQL عبر `bash deploy/backup-postgres.sh`. يتحقق السكربت من صلاحية الأرشيف قبل حفظه. اختبر الاستعادة إلى قاعدة منفصلة عبر `BACKUP_FILE=/path/to/hawdh-backup.dump TARGET_DB=hawdh_restore_check bash deploy/restore-postgres.sh`؛ يرفض السكربت الكتابة فوق قاعدة الإنتاج. احفظ النسخة وبصمتها في مكان مشفر خارج الخادم، واختبر الاستعادة دورياً؛ وجود ملف النسخ وحده لا يثبت إمكانية الاستعادة.

## الأمان وحدود الجاهزية

توجد أدوار وصلاحيات على الصفحات وملفات التصدير، كلمات مرور بحد أدنى 12 حرفاً، قفل بعد خمس محاولات فاشلة، تحديد لمحاولات تسجيل الدخول حسب عنوان IP، كوكي جلسة HttpOnly وSameSite، حماية CSRF، وسياسات أمان للمتصفح ومنع تخزين الصفحات المسجلة مؤقتاً. يُفرض التحقق بخطوتين على حساب المدير؛ ويُتاح له إعداد تطبيق المصادقة أول مرة قبل السماح باستخدام صفحات الإدارة.

حزمة Compose الإنتاجية تهيئ HTTPS، قاعدة PostgreSQL، قائمة المضيفين المقبولة، الوكيل العكسي الموثوق، مفتاح حماية الجلسات الدائم وفحص جاهزية قاعدة البيانات. إنشاء المستخدمين يتم عبر المدير، وتأكيد الحساب مطلوب. يلزم إعداد SMTP آمن (TLS) في `deploy/.env.production` لإرسال روابط تأكيد البريد وتغييره واستعادة كلمة المرور؛ يتوقف التطبيق الإنتاجي عند غياب الإعدادات المطلوبة حتى لا يعرض نجاحاً وهمياً. راجع [تقرير المراجعة الأمنية](docs/security-review/ar.md). لا تستخدم النسخة للفوترة الرسمية أو البيانات المالية الحقيقية قبل تشغيل نسخ احتياطية مشفرة خارج الخادم واختبار الاستعادة، وإعداد المراقبة والتنبيه، وإجراء مراجعة أمنية مستقلة.

سياق بناء Docker يستثني قواعد SQLite المحلية، مجلدات البناء، وملفات الأسرار وإعدادات التطوير حتى لا تدخل بيانات الجهاز في صورة الإنتاج.

## خصوصية المستودع

المشروع مهيأ لمستودع GitHub **خاص**، لكن لم يُنشأ مستودع GitHub أو تُرفع ملفات إلى الخارج. لا تحفظ بيانات حقيقية أو كلمات مرور أو أسرار اتصال في Git؛ `.gitignore` يستثني البيانات المحلية و`.env`. لا يوجد ترخيص مفتوح المصدر قبل تحديد مالك المشروع وحقوق التوزيع.
