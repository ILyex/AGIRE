# قرارات معمارية أولية

## ADR-001 — واجهة مشتركة وخادم مركزي

**الحالة:** مقترح بناءً على طلب استخدام عدة موظفين من أجهزة مختلفة.

**القرار:** تطبيق ويب مركزي عربي/فرنسي مبني بـ ASP.NET Core Blazor Server، مع PostgreSQL خلف الخادم. تُستضاف المنصة على خادم داخل مقر المؤسسة أو استضافة خاصة معتمدة. أجهزة المستخدمين لا تتصل بقاعدة البيانات مباشرة.

**الأسباب:** مصدر بيانات واحد، دعم الاستخدام المتزامن، صلاحيات مركزية، نسخ احتياطي منظم، وإمكانية الوصول من أجهزة متعددة. ملف EXE منفرد لا يوفر مزامنة آمنة بحد ذاته؛ يمكن إضافة مشغّل Windows لاحقًا للواجهة نفسها.

**الحدود التشغيلية:** الخادم والشبكة مطلوبان للوصول المشترك. يجب تحديد خطة اتصال احتياطية واستعادة الخدمة قبل التشغيل الفعلي.

يتطلب تشغيل الإنتاج مزود SMTP مضبوطاً عبر متغيرات البيئة لإرسال تأكيد البريد وتغييره واستعادة كلمة المرور. لا يُقبل اتصال SMTP دون TLS في الإنتاج، ولا يخزن المستودع بيانات الاعتماد.

## ADR-002 — لا تثبيت على أجهزة الموظفين

**القرار:** تقديم الواجهة من الخادم عبر HTTPS؛ يستخدم الموظف متصفحًا موجودًا أصلًا على جهازه. لا يتطلب التشغيل تثبيت إضافات أو بيئة تشغيل أو عميل قاعدة بيانات. يبقى إعداد الخادم وتحديثه مسؤولية مسؤول النظام.

**السبب:** خفض خطوات البدء وتجنب اختلاف نسخ العميل بين الموظفين. يمكن لاحقًا تغليف واجهة الويب في مشغّل اختياري إذا ثبتت حاجة تشغيلية لذلك، من دون نقل قاعدة البيانات إلى أجهزة المستخدمين.

## ADR-004 — حزمة نشر خاصة خلف وكيل موثوق

**القرار:** يوفر `docker-compose.production.yml` PostgreSQL على شبكة داخلية، وتطبيق الويب دون منفذ عام، وCaddy للإنهاء التلقائي لـ TLS. يقبل ASP.NET Core ترويسات `X-Forwarded-*` من عنوان Caddy الثابت المحدد فقط، ويشترط `AllowedHosts` وقاعدة PostgreSQL ومساراً دائماً لمفاتيح Data Protection في الإنتاج. فحص الصحة يتحقق من اتصال قاعدة البيانات.

**حدود القرار:** هذا الإعداد يتطلب نطاقاً يشير إلى الخادم والمنفذين 80 و443 متاحين لإصدار الشهادة. لا يضبط جدار الخادم أو DNS أو قرصاً مشفراً أو تنبيهات تشغيلية. قاعدة البيانات وحلقة المفاتيح تبقيان على مضيف Docker؛ يجب حماية المضيف والـ volumes وتخزين نسخ احتياطية مشفرة خارج الخادم واختبار استعادتها. إضافة نسخ تطبيق متعددة تتطلب تخزيناً مشتركاً محمياً للمفاتيح وخطة ترحيل تمنع سباق migrations.

## ADR-003 — جلسات ويب آمنة وحسابات فردية

**القرار:** حسابات فردية ينشئها المسؤول، ASP.NET Core Identity أو موفر هوية موثوق، أدوار مبدئية (مدير/موظف/قراءة فقط)، وفرض المصادقة متعددة العوامل على المديرين قبل استخدام صفحات الإدارة. تبقى صفحات إعداد تطبيق المصادقة متاحة للمدير الجديد لإتمام الإعداد الأولي. تُستخدم جلسات كوكي آمنة فقط عبر HTTPS، مع انتهاء وإبطال من جهة الخادم، وتحديد معدل محاولات الدخول، وحماية CSRF للعمليات المغيّرة للحالة.

**قاعدة مهمة:** لا تحفظ أسرار الجلسة أو رموز الدخول في `localStorage`، ولا تعتبر إخفاء عنصر في الواجهة بديلًا عن فحص الصلاحية داخل الخادم. تفعّل سياسة `Secure` و`HttpOnly` و`SameSite` الملائمة وتُراجع إعدادات الكوكي مقابل طريقة تسجيل الدخول. ([OWASP — إدارة الجلسات](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)، [Microsoft — SameSite في ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/security/samesite?view=aspnetcore-10.0))

كلمات المرور تُخزّن بتجزئة تكيفية مملحة عبر حل موثوق، ولا تُرسل أو تحفظ كنص صريح. المصادقة المتعددة العوامل تقلل أثر سرقة كلمة المرور، وتوصي OWASP بتحديد محاولات الدخول. ([OWASP — تخزين كلمات المرور](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)، [OWASP — المصادقة](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html))

يجب تفعيل HTTPS، بما في ذلك على شبكة المؤسسة؛ متصفح العميل لا يُطلب منه تجاوز تحذير شهادة. واجهات الكوكي تتطلب حماية CSRF المناسبة. ([Microsoft — حماية CSRF](https://learn.microsoft.com/en-us/aspnet/core/security/anti-request-forgery?view=aspnetcore-10.0))

## تدفق المنصة الحالية والطبقات المستهدفة
النسخة الحالية تشغّل الواجهة وفحوص الصلاحيات داخل تطبيق Blazor Server؛ أجهزة الموظفين لا تتصل بـ PostgreSQL مباشرة. المخطط والطبقات أدناه تصف اتجاهاً مستهدفاً للتوسع، وليست مشاريع منفصلة موجودة حالياً.

```text
متصفح الموظف (عربي/فرنسي، RTL/LTR)
              │ HTTPS
              ▼
        تطبيق ASP.NET Core Blazor Server
     ┌────────┼───────────┐
     ▼        ▼           ▼
 هوية وصلاحيات  منطق المجال  تصدير XLSX
              │
              ▼
       PostgreSQL مركزي
              │
       نسخ احتياطية محمية
```

## حدود المكونات

- **Web:** صفحات وتجربة استخدام وترجمات؛ لا تحتوي على أسرار اتصال قاعدة البيانات.
- **API:** هوية، تحقق من المدخلات، صلاحيات، تنسيق الأخطاء، واجهات واضحة للإصدار.
- **Domain/Application:** قواعد العميل والفاتورة والدفعة والاستهلاك، مستقلة قدر الإمكان عن الويب والتخزين.
- **Infrastructure:** PostgreSQL، ترحيلات قاعدة البيانات، سجلات التدقيق، التصدير والنسخ الاحتياطي.
- **Deploy:** إعداد تشغيل الخادم وقاعدة البيانات، فحوص الجاهزية والنسخ الاحتياطية، دون أسرار ثابتة في Git.

## اتساق البيانات المالية

- تمثل الدفعات سجلات مستقلة غير قابلة للحذف الصامت؛ الرصيد يُحسب من الفواتير والدفعات المسندة إليها.
- استخدام المعاملات عند إصدار فاتورة أو تسجيل دفعة وربطها. (مطبق حالياً على إصدار الفواتير وتسجيل الدفعات وقراءات الاستهلاك.)
- تمثيل المال بأرقام عشرية مناسبة، وعدم استخدام أعداد الفاصلة العائمة للحسابات المالية.
- تحفظ قراءة الاستهلاك الفترة والعدادات والتعرفة المطبقة، وتحفظ الفاتورة الناتجة المبلغ المحسوب. سجل القراءة هو الذي يؤرخ التعرفة؛ لا يوجد حقل مستقل للتعرفة في الفاتورة.
- العمليات الحساسة تسجل المستخدم والتوقيت والقيم قبل/بعد بحسب السياسة.

## المستودع والبيانات

- GitHub يُنشأ مستقبلًا بوضع **Private**؛ الخصوصية تحدد عند إنشاء المستودع ولا يمكن ضمانها بملف داخل Git.
- ملفات قواعد البيانات والنسخ والصادرات وملفات البيئة والأسرار مستبعدة في `.gitignore`.
- أمثلة التطوير تستخدم بيانات اصطناعية فقط.
- لا تُضاف رخصة مفتوحة المصدر قبل تأكيد المالك وحقوق النشر والتوزيع.

## بنية المجلدات المستهدفة

```text
docs/                     المتطلبات وقرارات التصميم AR/FR
prototype/                النموذج السابق للرجوع إليه
src/web/                  واجهة الويب
src/api/                  واجهة API والخدمات
src/domain/               نماذج وقواعد المجال
src/infrastructure/       التخزين والتكاملات
deploy/                   إعداد الاستضافة
scripts/                  أوامر التطوير والصيانة
```

## قرارات مؤجلة

استضافة داخلية أم سحابية، مزود الإشعارات، الضرائب وقواعد التعرفة المتقدمة، صيغة المستندات الرسمية، الحاجة للعمل دون اتصال، وملكية الرخصة. العملة التشغيلية محددة بالدينار الجزائري، والتعرفة الحالية مبلغ ثابت للمتر المكعب يحدده المدير.
